# Краткий рассказ для защиты задания 5

Основной скрипт я написал на Bash. Его задача — сохранить логи приложения и освободить место, не удаляя сами лог-файлы.

Сначала проверяется пользователь. Скрипт работает только от root, потому что обращается к системным папкам. Если каталог логов отсутствует, он создается, а сообщение записывается в журнал.

Далее скрипт получает блокировку. Она не позволяет двум бэкапам работать одновременно. Учебное приложение использует тот же файл блокировки, поэтому не записывает данные во время архивации и очистки.

Команда find находит обычные файлы с окончанием .log непосредственно в /var/log/app. Команда tar собирает их в один архив и сжимает его gzip. В имени архива есть дата и время. Архив сохраняется в /opt/backups.

Сразу после tar я сохраняю его код возврата в переменную. Ноль означает успех. Если код другой, исходные логи не очищаются. Также проверяется, что готовый архив читается.

После успешного сохранения архива команда truncate устанавливает размер исходных файлов в ноль. Файлы остаются на месте, их inode и права не меняются. Приложение может продолжить запись.

Затем скрипт проверяет возраст архивов. Если время изменения архива старше семи суток, архив удаляется. Посторонние файлы в папке бэкапов не затрагиваются. В журнал записывается количество удаленных архивов.

Все сообщения о работе скрипта содержат дату и время и записываются в /var/log/backup_script.log.

В root crontab установлена строка `0 2 * * * /usr/local/sbin/backup_and_clean.sh >/dev/null 2>&1`. Она означает ежедневный запуск в 02:00 по часовому поясу Linux. В стенде выбран Asia/Barnaul.

Работу я продемонстрировал в локальном Linux-контейнере Ubuntu. В тесте настоящий cron самостоятельно запустил скрипт по временному минутному расписанию. Ждать наступления 02:00 для проверки не потребовалось. В постоянном учебном стенде осталось ежедневное расписание на 02:00.

Размещение на Beget не выполнено. Пользователь сообщил, что воспользоваться хостингом не удается; на официальном сайте есть сообщение о восстановительных работах после атаки. Скриншот приложен к отчету. Это ограничение указано по дополнительному условию задания.

## Что нужно запомнить

- `$EUID` — идентификатор эффективного пользователя; у root он равен 0.
- `$?` — код завершения последней команды.
- `tar` объединяет файлы; `gzip` сжимает данные.
- `truncate -s 0` обнуляет файл, сохраняя его существование и inode.
- `flock` — добровольная блокировка; приложение тоже должно ее соблюдать.
- `RETENTION_DAYS=7` задает срок хранения. Для двух недель нужно поставить 14.
- `30 3 * * *` означает каждый день в 03:30.
- `cron` работает только при включенном Linux и работающем планировщике.
- Архивы локальные. Передача на другой сервер в этом решении не реализована.
